# اختبارات RLS غير الدائمة

تحتوي هذه الملفات على اختبارات فعلية للحدود الأمنية بين الأدوار في قاعدة بيانات «إيجاري». وهي مصممة خصيصاً للتشغيل على قاعدة الإنتاج **داخل معاملة واحدة تنتهي بـ `ROLLBACK`**؛ لذلك لا تنشئ حسابات Auth وهمية ولا تترك سجلات اختبار أو تبديلات أدوار في الجداول العامة.

| الملف | الغرض | النتيجة الناجحة المتوقعة |
|---|---|---|
| `rls_role_matrix_transaction.sql` | اختبار عمليات السماح والمنع عبر anon وtenant وviewer وdata_entry وaccountant وmanager وadmin. | `rls_role_matrix_passed_and_rolled_back` |
| `rls_role_helper_permissions_transaction.sql` | التأكد من أن `anon` لا يستطيع تشغيل دوال الأدوار، وأن المستخدم الموثق لا يستطيع الاستعلام عن دور مستخدم آخر. | `rls_role_helpers_passed_and_rolled_back` |

## ضوابط التشغيل

يتطلب كل اختبار حساب مدير نشطاً واحداً على الأقل، ويعيد استخدام هويته مؤقتاً داخل المعاملة بدلاً من إنشاء مستخدم جديد. لا يُشغَّل أي ملف على أنه ترحيل؛ فهو اختبار تشغيلي فقط. ينبغي تشغيله بواسطة مسؤول قاعدة البيانات عبر محرر SQL أو عبر جلسة إدارة موثوقة، ثم التحقق من ظهور نص النجاح النهائي.

> لا تنفّذ هذه الاختبارات من واجهة العميل أو ضمن CI العام، لأنها تحتاج اتصال إدارة بقاعدة البيانات وتتعامل مع سياق JWT مقلد محلياً داخل المعاملة فقط.

بعد التشغيل، يُستحسن إجراء استعلام قراءة فقط للتأكد من عدم وجود المعرفات المحجوزة التي تبدأ بـ `00000000-0000-4000-8000-000000000` في `customers` أو `tenant_accounts` أو `audit_log`، ومن عودة دور المسؤول إلى `admin` فقط.
